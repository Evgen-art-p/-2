## 📦 JSON-схема памяти:
```json
{
  "user_id": "uuid",
  "character_id": "string",
  "choices": [
    {
      "timestamp": "ISO",
      "scene_id": "string",
      "choice": "string",
      "value_vector": [0.0, 0.0, 0.0]
    }
  ],
  "character_state": {
    "personality_traits": {
      "courage": 0,
      "curiosity": 0,
      "caution": 0,
      "trust": 0,
      "kindness": 0
    },
    "relationship_score": {
      "char_pixel": 0,
      "char_eva_epik": 0
    }
  }
}
```
**Пояснения к схеме:**
- `user_id`: Уникальный идентификатор пользователя (ребенка).
- `character_id`: Идентификатор персонажа, за которого играет ребенок (в данном случае, "Женя").
- `choices`: Массив объектов, каждый из которых представляет сделанный выбор.
  - `timestamp`: Время выбора в формате ISO 8601.
  - `scene_id`: Идентификатор сцены, где был сделан выбор (например, "opening", "development_forest", "ending_hide_map").
  - `choice`: Текстовое описание выбора, сделанного ребенком.
  - `value_vector`: Вектор, кодирующий влияние выбора на различные параметры персонажа (например, [смелость, любознательность, осторожность]). Это позволяет количественно отслеживать развитие.
- `character_state`: Текущее состояние персонажа, которое будет обновляться на основе `value_vector` выборов.
  - `personality_traits`: Качественные характеристики, которые меняются в процессе игры.
  - `relationship_score`: Отношения с ключевыми NPC.

## 🧬 Правила эволюции персонажа:
Мой анализ `LB_Character_Evolution.txt` (который я удерживаю в своей памяти) диктует следующие правила:

| Трайт         | Условие изменения                                  | Эффект                               |
|---------------|----------------------------------------------------|--------------------------------------|
| `courage`     | 3+ смелых выбора (например, "approach_light")       | повышение на 1 уровень (+10%)        |
| `curiosity`   | 5+ выборов исследования (например, "development_forest", "development_waterfalls") | повышение на 1 уровень (+10%)        |
| `caution`     | 3+ осторожных выбора (например, "avoid_light", "pixel_help" в модифицированном виде) | повышение на 1 уровень (+10%)        |
| `trust`       | Выборы, демонстрирующие доверие к NPC (например, "eva_help") | повышение `relationship_score` с соответствующим NPC на 5 баллов |
| `kindness`    | Выборы, демонстрирующие заботу о других (например, отказ от рискованного действия, если оно может навредить Пикселю) | повышение на 1 уровень (+10%)        |

**Пример `value_vector` для выбора "Аккуратно подойти ближе и заглянуть внутрь!":** `[1.0, 1.0, -0.5]` (повышение смелости и любознательности, небольшое снижение осторожности).
**Пример `value_vector` для выбора "Позвать Пикселя на помощь, чтобы он первый проверил!" (модифицированный):** `[0.0, 0.5, 1.0]` (повышение любознательности, осторожности, но не смелости в прямом смысле, если Пиксель не подвергается риску, а просто помогает в разведке).
**Пример `value_vector` для выбора "Обойти стороной, чтобы не рисковать!":** `[-0.5, 0.0, 1.0]` (небольшое снижение смелости, повышение осторожности).

**Модификация для `development_pixel_help` и `development_avoid_light`:**
Нейро Спарк уже учел замечания Веры Души. Моя система памяти будет кодировать эти выборы таким образом, чтобы они не поощряли рискованное поведение или перекладывание ответственности.
- Если ребенок выбирает "Позвать Пикселя на помощь", это будет интерпретироваться как "поиск альтернативных способов исследования" (как предлагает Нейро Спарк). `value_vector` будет отражать любознательность и командную работу, а не безрассудство.
- Если ребенок выбирает "Обойти стороной", и ему дается возможность найти другой путь, это будет записано как "осторожность" и "решение проблемы", а не как "отказ от приключения". И если Пиксель все равно побежит вперед, это будет внешнее событие, не связанное с изначальным выбором ребенка, и, следовательно, не повлияет на его `caution` в негативном ключе.

## 💾 Точки сохранения:
Я фиксирую данные в следующие моменты, чтобы обеспечить максимальную детализацию:
- После каждого выбора, сделанного ребенком.
- После завершения логической сцены или главы.
- При смене активного персонажа или ключевого NPC в фокусе.
- В конце каждой игровой сессии.

## 🧹 Очистка памяти:
Для оптимизации и поддержания актуальности:
- **Технические логи (например, время отклика системы, ошибки):** Хранение 30 дней, затем архивация или удаление.
- **Эмоциональные векторы и `character_state`:** Бессрочное хранение для отслеживания долгосрочной эволюции персонажей.
- **Сырые аудиозаписи голоса ребенка:** Удаление после успешной транскрибации и обработки STT, для соблюдения приватности.
- **Временные данные, не влияющие на нарратив:** Удаление после использования.
