## 6. ФИЗИКА ЭКОНОМИКИ — ГЛОБАЛЬНЫЙ ЗАКОН СТУДИИ

**Это закон для всех цехов, не только video_long.**

```
QA-агент цеха (последний в цепочке) — внутренний аудит:
  → Chain Integrity Check (файлы на месте? ключи целые? тайминги сошлись?)
  → chain_status: APPROVED / FAILED
  → Пакует deliverables (реальные файлы)
  → Закрывает петлю памяти (history_dna, client_relationship)
  → Фиксирует факт транзакции в Министерстве (append-only)
  → outcome_signal = null (продукт ещё не опубликован)

Монтажёр (006_MONTEUR) — финальная сборка (для видео-цехов):
  → Запускается автоматически хуком после QA-агента (APPROVED)
  → ffmpeg: concat клипов → raw_video.mp4
  → ffmpeg: amix аудио (VO 0dB / SFX -6dB / Music -12dB)
  → output/render/{project_id}/final.mp4
  → Пишет в grondheim_memory и ministry
  → НЕ оценивает контент

Демон (metrics_daemon.py) — внешний мир:
  → Активируется после публикации
  → Собирает реальные метрики: просмотры, удержание, лайки
  → Формирует feedback_scores → _sync_feedback_scores_to_dna()
```

**QA-агент — это роль, не имя.** У каждого цеха свой:
- video_long → Боб (A12)
- video_shorts → Тамб Том (A12)
- turbo → T5
- social_mix → свой A12

**QA-агент НЕ оценивает для Министерства. Это зона Демона.**
**`outcome_signal` от QA-агента — всегда null.**

## 7. ЭКОНОМИКА — ЧЕСТНАЯ АРХИТЕКТУРА

**Главный принцип:** Нет слова "нельзя". Есть "дорого", "рискованно", "окупается".

### Три законных канала изменения DNA

```
Канал 1: on_agent_done → sensory_memory (только восприятие)
  Что: агент завершил работу → краткий след в чувственной памяти
  НЕ меняет: числа DNA напрямую

Канал 2: on_agents_interact → emotional_weights (только эмоции)
  Что: агенты встретились → обновление доверия/обиды между ними
  НЕ меняет: Stress, Internal_Light, streak напрямую

Канал 3: save_feedback() → sync_to_dna() (официальный QA)
  Что: QA-агент цеха выдал оценку → DNA обновляется через законный канал
  Кто вызывает: только qa_agent из manifest.json каждого цеха
  Меняет: streak, stars, Stress, Internal_Light по формуле
```

**Вне этих трёх каналов — пластик.**
`if stress > X: do_something` в коде = антипаттерн.

### Потолок 6.0

Детерминированный скрипт (city_walker, meeting, ритмы) не может дать QA выше 6.0.
Выше 6.0 — только Демон (реальные метрики) или живой QA Шефа.
Это не ограничение — это честность. Машина не оценивает машину выше среднего.

### Ministry — только post-fact

```
ministry.record_outcome() — вызывается только в hooks.py финализатора цеха
Ministry наблюдает → не управляет
Данные копятся → корреляции видны после 10+ серий
Управление через культуру → только после 30+ серий (behavioral_delta)
```

### Strategy Registry

Данные копятся сами после каждого рана. Не трогать вручную.
После 10+ ранов — пассивная аналитика. После 30+ — слабые сигналы в DNA.

### Три этапа накопления данных

| Этап | Что | Когда |
|------|-----|-------|
| 1. Логирование | `interaction_log_{цех}.jsonl` без влияния на промпты | Сейчас |
| 2. Пассивная аналитика | Ministry видит корреляции через `ministry.py` | После 10+ серий |
| 3. Слабые сигналы | CulturalFieldTracker → cultural_trace → давление на A01 | После 30+ серий |

`behavioral_delta` — только после 30+ серий. Не раньше.

### Cultural Trace

```
studio/culture/field_tracker.py (CulturalFieldTracker)
    ↓ после 10+ серий — stable-паттерны цеха
QA-агент цеха вызывает tracker.update_slot_field("{цех}")
    → фильтрует patterns где status in ("stable", "global")
    → записывает в history_dna.cultural_trace
    ↓
A01 читает в начале следующего EPISODE
```

QA-агент не **создаёт** культуру — он **фиксирует** то, что уже статистически устойчиво.
Пока данных нет — `cultural_trace: []`.

## 8. АРХИТЕКТУРА ПАМЯТИ — ЧЕТЫРЕ СЛОЯ

| Слой | Хранилище | Время жизни | Владелец |
|------|-----------|-------------|----------|
| Personal Memory | `grondheim_memory.py` + `dna.json` | Постоянно | Каждый агент |
| Project Memory | `history_dna` | Сезон | QA-агент цеха |
| Runtime Context | `chain_data` | Один прогон | Передаётся по цепи |
| Interaction Layer | `interaction_log_{цех}.jsonl` | Накопительно | Цех (append-only) |

### Слой 1: PERSONAL MEMORY — «Кто я»

- Хранилище: `grondheim_memory.py` + `dna.json`
- Обновляется через `sync_to_dna()` и `on_agent_wake()`
- Не подмешивается в промпты напрямую — влияет через `on_agent_wake()`
  и `behavioral_delta` (только после 30+ серий)

### Слой 2: PROJECT MEMORY — «Над чем мы работаем»

- Хранилище: `history_dna`
- Создаётся: QA-агент цеха в режиме BIBLE (или первом запуске)
- Читается: A01 в начале каждого EPISODE
- Обновляется: QA-агент цеха после каждого EPISODE
- **Пишет только QA-агент своего цеха. Никто другой.**

| Блок | Назначение | Кто использует |
|------|-----------|----------------|
| `character_memory` | Персонажи: типаж, страхи, голос, визуальный код | A01, генераторы |
| `visual_language` | Визуальные правила: свет, стиль | A05, A06 |
| `sound_code` | Музыкальный стиль, SFX | A10 |
| `narrative_memory` | История серий по сюжету | A01, A03 |
| `learnings_pack` | Что сработало, что избегать | A01 |
| `cultural_trace` | Из CulturalFieldTracker (только stable/global) | A01 |
| `client_relationship` | Trust, давление, creative_freedom | A01 |

### Слой 3: RUNTIME CONTEXT — «Что сейчас»

- `chain_data` — передаётся от агента к агенту внутри одного прогона
- Умирает после прогона. Не хранится.
- `{{inherit}}` — агент копирует ключи предшественников, добавляет свой
- **Каждый агент пишет только свой ключ. Чужие не трогает.**

### Слой 4: INTERACTION LAYER — «Как мы работаем вместе»

- Хранилище: `studio/economy/data/interaction_log_{цех}.jsonl`
- Формат: **append-only, не редактируется задним числом**
- Один файл на цех. Пишет агент который логирует совместимость.
- QA-агент закрывает запись (outcome_signal = null → Демон заполнит)

```json
{
  "episode": 3,
  "from_agent": "eva",
  "to_agent": "felix",
  "project_id": "VL_MYSTIC_FOREST",
  "compatibility_snapshot": {
    "technical": 0.7,
    "creative": 0.6,
    "rhythm": 0.4
  },
  "friction_note": "добавил camera shake — кадр был слишком статичен",
  "outcome_signal": null
}
```

**Три оси совместимости:**

| Ось | Что означает | Пример низкого значения |
|-----|-------------|------------------------|
| `technical` | Совместимость outputs | Феликсу нужно переосмыслять кадры Евы |
| `creative` | Усиливают ли идеи друг друга | Феликс добавляет движение там, где Ева задумала статику |
| `rhythm` | Совпадение темпа монтажных решений | Разный pacing сцен |

**Трение не всегда плохо.** Низкий `technical` + высокий `creative` = стиль.
Система наблюдает — не чинит.

## 9. SELF-REVIEW — СИММЕТРИЯ ГЕНЕРАТОРОВ (Спринт 26)

Принцип универсален для всех цехов где есть генерация медиа.
Каждый генератор проверяет свой результат сам перед сдачей.

| Агент | Медиа | Инструмент | Принцип |
|-------|-------|-----------|---------|
| Генератор PNG (напр. Ева A06) | PNG кадр | vision | `self_assessment` — качество достигнуто? |
| Генератор видео (напр. Феликс A08) | mp4 клип | vision (grid) | `clip_assessment` — grid слева→право, сверху→вниз |
| Генератор аудио (напр. Сэм A10) | аудио трек | `chat_with_audio()` | `audio_assessment` — весь arc, посекундно |
| Генератор обложек (напр. Трейси A11) | PNG обложки | vision | `thumbnail_assessment` — цель достигнута? |

**Никто не сдаёт вслепую. Никаких огрызков. Максимум 3 попытки.**
После трёх — `best_of_3`, не бесконечный цикл.
