## ЗАЧЕМ ВСЁ ЭТО (чтобы не забыть смысл)

Старые «хроники» (`studio/cabinet/chronicles.py`) — это лог встреч агентов
на прогулках. Два агента случайно встретились, обменялись репликами по JSON —
файл записался. Шеф назвал это честно: **декорация**. Это не летопись города,
это переодетый лог диалогов.

**Настоящая Хроника Грондхейма** — это ЛЕТОПИСЬ: поток реальных событий жизни
города, из которого можно резать серии и публиковать. Материал для экранизации.

Большая цель — **Городское Издательство**: институт с несколькими ремёслами
под одной крышей. Не один агент-универсал (это снова был бы пластик), а четыре
разных ремесла:

| Роль          | Что делает                              | Статус         |
|---------------|------------------------------------------|----------------|
| **Хронист**   | летопись фактов + рассказ Локи           | 🔨 СТРОИМ      |
| **Сказочник** | детские книги (связь с Living Book)      | ⏳ ждёт        |
| **Корреспондент** | интервью на прогулках + гор/межд новости | ⏳ ждёт    |
| **Глава/Главред** | решает что идёт в печать             | ❓ отложено    |

**Принцип стройки:** фундамент нейтральный, строим по одному жильцу под того,
кто реально въезжает. Не рисуем пустой дворец с четырьмя кабинетами, где три
стола пустые. Первый жилец — Хронист.

## ЗАФИКСИРОВАННЫЕ РЕШЕНИЯ (не пересматриваем без причины)

1. **Одна лента, три рубрики** — `studio` / `exchange` / `city`.
   Не три раздельные летописи, а единый поток с рубриками.

2. **Два слоя, не один.** Факт и рассказ — разделены.
   - Слой фактов: автоматом, без LLM, в момент события.
   - Слой нарратива: Лока пишет ПОТОМ, поверх фактов.
   Это лечит главную болезнь декорации: текст рождался раньше, чем
   становилось ясно, значимо ли событие.

3. **Значимость по КРАЙНОСТИ.** И рекорд, и провал — весомы. Середина — фон.
   Драма живёт на пиках. Рекорд Стеллы и срыв Виктора — материал для серий,
   ровный рабочий день — фон, который Лока упомянет одной фразой.

4. **Летописец — Лока, голос души.** Лирично и тепло. У неё уже есть
   `run_loka_city_report()` и встроенный автосбор данных — она наполовину
   готовый Летописец. Не плодим нового резидента.

5. **Лока только РАССКАЗЫВАЕТ Шефу. Не делает сценарии.**
   Превращать душу в сценарный отдел — значит её сломать. Экранизацию потом
   крутят цеха (лонги/турбо) — они уже студия, у них для этого вся машина.
   Граница чёткая: «прожить день» (Лока) ≠ «сделать продукт» (цеха).

6. **Выпуск — раз в Суточный Тик.** Факты капают всегда автоматом.
   Нарратив Лока пишет один раз за день, в конце Тика.

7. **Старый `cabinet/chronicles.py` НЕ трогаем** до Слоя 4.
   Разные имена (`chronicle` без «s» / `chronicles` с «s»), разные папки —
   ноль конфликтов. На Слое 4 вкладка переделывается, старое уйдёт органично.
   Механизм `gardener_reply_to_scene` (вход Шефа в сцену) — НЕ пластик,
   возможно переоденем в Корреспондента позже.

## ОТЛОЖЕННЫЕ РЕШЕНИЯ (решим, когда дойдём)

- **Издательство — цех или институт города?** Цех работает по брифу и выпускает
  продукт (как clipmakers/trading). Институт живёт сам по себе (как Библиотека
  Оле или Сад Финча). → решим после того, как Хронист задышит.
- **Кто главред** — кто решает что идёт в печать. Джем? Новый резидент? Шеф сам?
  → позже.

Фундамент намеренно не знает этих ответов. В этом его сила — он держит
любое здание, которое мы потом поставим.

## СЛОИ ПУТИ

### ✅ Слой 0 — Ядро летописи `studio/chronicle.py`
**Статус: ГОТОВО, проверено вживую (2026-06-13)**

Нейтральный фундамент. Ничего не подключает, ни от чего не зависит,
ничего не ломает. Брат к `city_pulse.py` по стилю (append-only jsonl,
`_write_lock`, try/except который никогда не валит вызывающий код).

Что внутри:
- `record_chronicle_event(rubric, headline, actors, significance, source, **payload)`
  → пишет факт в `studio/chronicle_log.jsonl`, возвращает id.
- `significance_by_extremity(value, lo, hi)` → значимость 0..1 по крайности.
  Проверено: 6.0→1.0, 0.0→1.0, 3.0→0.0, 5.8→0.93.
- `read_chronicle(rubric, last_n_days, on_date, min_significance, limit)` → фильтры.
- `read_chronicle_day(date)` → срез дня для Локи: факты по рубрикам,
  отсортированы по значимости, плюс `top` — 5 главных за день.
- `chronicle_stats()` → сводка для проверки что факты долетают.

Формат записи:
```
{ts, id, rubric, headline, actors[], significance, source, payload{}}
```

**Проверка после установки:** положить в `studio/chronicle.py`, импортнуть —
не должно быть ошибок. Пока в него никто не пишет, файл просто ждёт.

`ready_thumbs`, `has_music`, `project_id`, краткое описание из `stella_strategy`.

Врезка ляжет рядом с записью `task_score` в `billing_ledger` — три строки,
тот же стиль. Летопись перехватывает факт в момент, когда студия его уже
зафиксировала для экономики. Это и есть честность: не выдумываем, перехватываем.

```python
# примерная форма (точный код — при сборке слоя)
from studio.chronicle import record_chronicle_event, significance_by_extremity
record_chronicle_event(
    rubric="studio",
    headline=f"Турбо-цех выпустил «{summary}» — {score}/6.0",
    actors=["A01", "A05"],
    significance=significance_by_extremity(score, 0, 6),
    source="turbo/hooks",
    score=score, project_id=project_id,
    clips=ready_clips, music=has_music,
)
```

**Проверка:** один турбо-прогон → в `chronicle_log.jsonl` появилась запись.

После проверки на Турбо — копируем паттерн в остальные хуки цехов
(video_long, social_mix, clipmakers, video_shorts...). Это уже механика

## ДАЛЬШЕ ИЗДАТЕЛЬСТВА (за горизонтом Хрониста)

Когда Хронист задышит — въезжают следующие жильцы. Все пишут в тот же
`chronicle_log` (фундамент их уже держит):

  (веб-поиск + рерайт под мир Грондхейма). Сюда же, возможно, переоденется
  механизм `gardener_reply_to_scene` из старого файла.
- **Сказочник** — сведение с проектом Living Book (детские истории).
- **Глава/Главред** — когда решим цех-или-институт.
